# 🚀 حزمة نشر نظام الحضور على خادم (NOCI Deploy)

تنقل النظام من جهاز التطوير إلى حاسبة الخادم (حاسبة التجربة أو الحاسبة الرئيسية)، وتربطه بالدومين **https://employee.nociraq.com** عبر Cloudflare Tunnel: دون IP ثابت، ودون فتح أي منفذ في الراوتر.

بُنيت على تجربة حزمة DMS-Toolkit من مشروع سابق، مع تبسيط مهم: نظامنا خادم Node واحد على المنفذ `5000` يقدّم الواجهة والـ API معاً، وقاعدة بياناته SQLite في ملف. فلا يحتاج IIS ولا SQL Server.

---

## 🗂️ المحتويات

| الملف | الجهاز | الوظيفة |
|---|---|---|
| `Run_Deploy_Menu.bat` | الكل | قائمة تفاعلية: اكتب رقم الخطوة. تطلب صلاحيات المسؤول تلقائياً. |
| `scripts/_common.ps1` | — | الإعدادات المشتركة: الدومين، ومجلد التثبيت `C:\NOCI`، والمنفذ، واسم المهمة والنفق. **غيّرها هنا فقط.** |
| `00-server-reset.ps1` | 🧪 التجربة | يحذف التثبيت والمهمة وخدمة النفق، ويحفظ قبلها نسخة من البيانات والمفاتيح في `C:\NOCI-reset-backup-*`. يطلب كتابة `RESET`. |
| `01-dev-build-and-pack.ps1` | 💻 التطوير | يشغّل الاختبارات، ويبني الواجهة، وينتج `releases\server\noci-server-<الإصدار>.zip` ومجلد `NOCI-Deploy` بجانبه. يرفض الحزمة إن احتوت بيانات أو مفاتيح أو `.env`، أو نقصت ملفات الواجهة. |
| `02-server-preflight.ps1` | 🖥️ الخادم | فحص فقط: الحزمة، وNode، والمنفذ 5000، والتثبيت السابق، والمساحة، والاتصال بـ Cloudflare. |
| `03-server-install.ps1` | 🖥️ الخادم | يفك الحزمة إلى `C:\NOCI`، ويكتب `.env` (`HOST=127.0.0.1`)، وينشئ القاعدة والمفاتيح وحساب `admin` بكلمة مرور مؤقتة تظهر **مرة واحدة**، ويقفل أذونات المفاتيح. يرفض العمل إن وُجد تثبيت. |
| `04-server-service.ps1` | 🖥️ الخادم | يسجّل الخادم كمهمة مجدولة بحساب SYSTEM تعمل عند الإقلاع، **قبل تسجيل الدخول**، وتُعاد إن توقفت. يحذف اختصار Startup القديم إن وجد. |
| `05-server-tunnel.ps1` | 🖥️ الخادم | يثبّت cloudflared (موقّعاً)، وينشئ النفق، ويربط الدومين، ويشغّله كخدمة ويندوز مع علاج العطل 7. |
| `06-server-verify.ps1` | 🖥️ الخادم | فحص شامل من 7 بنود، يشمل الدومين من الإنترنت. |
| `07-server-update-release.ps1` | 🖥️ الخادم | تحديث نسخة عاملة مع الحفاظ على البيانات، ولقطة تراجع، وتراجع تلقائي عند الفشل. |
| `08-server-cloudflared-update.ps1` | 🖥️ الخادم | تحديث cloudflared عند التنبيهات الأمنية، مع التحقق من التوقيع والتراجع التلقائي. |

## 1️⃣ على جهاز التطوير

1. شغّل `toolkit\deploy\Run_Deploy_Menu.bat` واختر **`1`**.
2. انسخ إلى الفلاشة من `releases\server\`:
   - الملف `noci-server-2.0.0.zip`
   - المجلد `NOCI-Deploy`

   ضعهما في جذر الفلاشة.

## 2️⃣ على الخادم: التثبيت أول مرة

**المتطلبات:**
- ويندوز 10 أو 11 متصل بالإنترنت.
- **Node.js بنفس الإصدار الرئيسي لجهاز البناء** (حالياً 24 LTS)، بملف `.msi` من https://nodejs.org ومثبتاً لكل المستخدمين.
- الوصول إلى حساب Cloudflare الذي يدير `nociraq.com`.

**الخطوات:** شغّل `NOCI-Deploy\Run_Deploy_Menu.bat` من الفلاشة، ثم نفّذ بالترتيب:

| الخطوة | ماذا تتوقع |
|---|---|
| **2** الفحص المسبق | كل البنود "نجح". |
| **3** التثبيت | **سجّل كلمة المرور المؤقتة لحساب `admin`**، فهي لا تُعرض مرة أخرى. |
| **4** الخدمة | الخادم يرد محلياً بالإصدار. |
| **5** النفق | يفتح المتصفح أول مرة: سجّل دخولك في Cloudflare، واختر `nociraq.com`، ثم Authorize. |
| **6** الفحص الشامل | 7 من 7. |

بعدها:
1. افتح **https://employee.nociraq.com** من الهاتف على بيانات الجوال، لا من شبكة الخادم.
2. ادخل بـ `admin` وكلمة المرور المؤقتة، ثم غيّرها.
3. استورد ملف الموظفين من شاشة الموظفين.

> **تطبيق الويندوز والآيفون:** من شاشة الدخول ← **"ضبط عنوان الخادم (API)"** ← `https://employee.nociraq.com/api`. أما الويب على الدومين فيتصل تلقائياً.

## 3️⃣ على الخادم: تحديث إصدار

1. على جهاز التطوير: الخطوة **`1`**.
2. انقل الحزمة الجديدة ومجلد `NOCI-Deploy` إلى الفلاشة.
3. على الخادم: الخطوة **`7`** فقط.

> ⚠️ **عند التحديث لا تشغّل أبداً الخطوة `0` ولا `3`.** الخطوة `7` تحافظ على كل شيء.

**ما لا يمسه التحديث أبداً** (داخل `C:\NOCI\backend`):
- `data`: قاعدة البيانات ونسخها الاحتياطية.
- `.keys`: مفاتيح التشفير، ولا تُكشف كلمات المرور المحفوظة بدونها.
- `uploads`: الصور والشعار.
- `logs`.
- `.env`.

## 🧭 أين كل شيء على الخادم

| المسار | المحتوى |
|---|---|
| `C:\NOCI\backend\data\attendance.db` | قاعدة البيانات |
| `C:\NOCI\backend\data\backups\` | نسخ تلقائية يومية (آخر 30) ونسخ يدوية |
| `C:\NOCI\backend\.keys\secrets.json` | مفاتيح JWT والتشفير. **انسخها مرة واحدة لمكان آمن خارج الحاسبة.** |
| `C:\NOCI\backend\logs\server.log` | سجل الخادم |
| `C:\NOCI\releases\` | لقطات التراجع (آخر 5) ونسخ cloudflared السابقة |
| `C:\Windows\System32\config\systemprofile\.cloudflared\config.yml` | إعداد النفق الذي تقرؤه الخدمة |

**أوامر مفيدة** (PowerShell كمسؤول):

إعادة تشغيل الخادم:
```powershell
Stop-ScheduledTask NociAttendanceServer; Start-ScheduledTask NociAttendanceServer
```

متابعة سجل الخادم مباشرة:
```powershell
Get-Content C:\NOCI\backend\logs\server.log -Tail 30 -Wait
```

إعادة تشغيل النفق:
```powershell
Restart-Service Cloudflared
```

## 🩹 أعطال معروفة وحلولها

| العَرَض | السبب | الحل |
|---|---|---|
| خدمة Cloudflared تبدأ ثم تتوقف فوراً | **العطل 7:** `cloudflared service install` يسجّل الخدمة بلا `--config`، فلا تجد إعدادها في حساب SYSTEM. | الخطوة 5 تنسخ الإعداد لحساب SYSTEM وتضبط `ImagePath`. الخطوة 8 تعيده كما كان بعد أي تحديث. |
| الدومين يعطي خطأ 1033 | النفق متوقف أو ملف اعتماده من حاسبة أخرى. | الخطوة 5 تكتشف ذلك وتعيد إنشاء الاعتماد. |
| الدومين يعطي خطأ 502 | النفق يعمل لكن الخادم متوقف. | الخطوة 6 لمعرفة السبب، ثم سجل الخادم. |
| الخادم لا يقلع وفي السجل `NODE_MODULE_VERSION` | إصدار Node مختلف عن جهاز البناء. | ثبّت نفس الإصدار الرئيسي، أو ابنِ الحزمة على جهاز بنفس الإصدار. |
| المنفذ 5000 مشغول | نسخة ثانية تعمل (مثلاً من `تشغيل النظام.bat` أو من اختصار Startup قديم). | أغلقها. الخطوة 4 تحذف الاختصار القديم تلقائياً. |
| واجهة قديمة بعد التحديث | ذاكرة المتصفح. | Ctrl+F5، أو أغلق التبويب وافتحه من جديد. |
| تنبيه أمني من Cloudflare عن إصدار cloudflared | الخدمة تعمل بـ `--no-autoupdate` فلا تتحدث وحدها. | الخطوة 8. |
