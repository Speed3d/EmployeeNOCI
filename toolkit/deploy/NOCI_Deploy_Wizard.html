تصفير حاسبة التجربة بالكامل (Reset to Clean State)
حذف مهمة الخادم وخدمة Cloudflared ومجلد التثبيت لإعادة التجربة من الصفر، مع نسخة أخيرة من البيانات
🧪 حاسبة التجربة
⚡ أمر التشغيل المؤتمت (يطلب كتابة RESET للتأكيد):
powershell -ExecutionPolicy Bypass -File E:\NOCI-Deploy\scripts\00-server-reset.ps1
أوامر التصفير اليدوية المباشرة (PowerShell كمسؤول) 
# 1. إيقاف الخادم وحذف مهمته
Stop-ScheduledTask NociAttendanceServer -ErrorAction SilentlyContinue
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like '*C:\NOCI*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Unregister-ScheduledTask NociAttendanceServer -Confirm:$false

# 2. حذف خدمة النفق وإعداداتها لحساب SYSTEM
Stop-Service Cloudflared -Force -ErrorAction SilentlyContinue; sc.exe delete Cloudflared
Remove-Item "C:\Windows\System32\config\systemprofile\.cloudflared" -Recurse -Force -ErrorAction SilentlyContinue

# 3. نسخة أخيرة من البيانات والمفاتيح قبل الحذف
$bk = "C:\NOCI-reset-backup-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
New-Item -ItemType Directory -Force $bk | Out-Null
Copy-Item "C:\NOCI\backend\data", "C:\NOCI\backend\.keys" $bk -Recurse -Force

# 4. حذف مجلد التثبيت
Remove-Item "C:\NOCI" -Recurse -Force
🎯 النتيجة المتوقعة بعد التصفير:
لا مهمة NociAttendanceServer ولا خدمة Cloudflared ولا مجلد C:\NOCI. البيانات محفوظة في C:\NOCI-reset-backup-*، والنفق باقٍ في حساب Cloudflare وتعيد الخطوة 5 استخدامه.
⚠️ أمان البيانات:
لحاسبة التجربة فقط. لا تشغّله على الخادم الرئيسي بعد بدء العمل الفعلي، ولا تشغّله أبداً بدل التحديث.

04
تشغيل الخادم الدائم مع الإقلاع (Startup Task)
مهمة مجدولة NociAttendanceServer بحساب SYSTEM تعمل عند الإقلاع قبل تسجيل الدخول، وتُعاد إن توقفت
🖥️ الخادم
⚡ أمر تسجيل الخدمة:
powershell -ExecutionPolicy Bypass -File E:\NOCI-Deploy\scripts\04-server-service.ps1
الأوامر اليدوية المكافئة 
$node = (Get-Command node).Source
$action = New-ScheduledTaskAction -Execute $node -Argument '"C:\NOCI\backend\scripts\run-forever.js"' -WorkingDirectory "C:\NOCI\backend"
$trigger = New-ScheduledTaskTrigger -AtStartup
$principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -LogonType ServiceAccount -RunLevel Highest
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -RestartCount 999 -RestartInterval (New-TimeSpan -Minutes 1) -ExecutionTimeLimit ([TimeSpan]::Zero)
Register-ScheduledTask -TaskName NociAttendanceServer -Action $action -Trigger $trigger -Principal $principal -Settings $settings
Start-ScheduledTask NociAttendanceServer

# التحقق
Invoke-RestMethod http://127.0.0.1:5000/api/system/status
🎯 النتيجة المتوقعة:
الخادم يرد محلياً بـ status: ONLINE والإصدار. السجل في C:\NOCI\backend\logs\server.log، والنسخة الاحتياطية التلقائية الأولى تُنشأ فوراً.
⚠️ لماذا ليس اختصار Startup:
اختصار مجلد Startup (install-startup-service.bat) لا يعمل إلا بعد تسجيل دخول مستخدم، ويتوقف عند تسجيل خروجه. السكربت يحذف الاختصار القديم إن وجد حتى لا تعمل نسختان على المنفذ نفسه.

نفق Cloudflare كخدمة ويندوز (Tunnel)
تثبيت cloudflared الموقّع، وإنشاء النفق، وربط employee.nociraq.com بالمنفذ 5000، مع علاج العطل 7
🖥️ الخادم
⚡ أمر إعداد النفق (يفتح المتصفح أول مرة لتفويض الدومين):

الأوامر اليدوية المفصلة 
# 1. التثبيت والتفويض
winget install --id Cloudflare.cloudflared --exact
cloudflared tunnel login                         # اختر nociraq.com ثم Authorize
cloudflared tunnel create noci-attendance-tunnel
cloudflared tunnel route dns --overwrite-dns noci-attendance-tunnel employee.nociraq.com

# 2. إعداد خاص بحساب SYSTEM (الخدمة لا ترى مجلد المستخدم)
$sys = "C:\Windows\System32\config\systemprofile\.cloudflared"
# انسخ إليه <TUNNEL-ID>.json و cert.pem من $env:USERPROFILE\.cloudflared، ثم config.yml:
#   tunnel: <TUNNEL-ID>
#   credentials-file: C:\Windows\System32\config\systemprofile\.cloudflared\<TUNNEL-ID>.json
#   ingress:
#     - hostname: employee.nociraq.com
#       service: http://localhost:5000
#     - service: http_status:404

# 3. الخدمة مع علاج العطل 7
cloudflared service install
$exe = (Get-Command cloudflared).Source
Set-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Services\Cloudflared" -Name ImagePath -Type ExpandString `
  -Value "`"$exe`" --config `"$sys\config.yml`" --no-autoupdate tunnel run"
Restart-Service Cloudflared
🎯 النتيجة المتوقعة:
https://employee.nociraq.com/api/system/status يرد. وفي لوحة Cloudflare: Networking ← Tunnels ← النفق Healthy. انتشار DNS أول مرة قد يأخذ دقائق.
⚠️ العطل 7 (من تجربة DMS):
cloudflared service install يسجّل الخدمة دون --config، فتبدأ ثم تخرج صامتة لأن حساب SYSTEM لا يجد الإعداد. لذلك يُنسخ الإعداد لمجلد SYSTEM ويُضبط ImagePath بـ --config وtunnel run.

تحديث نسخة مرفوعة بأمان (In-Place Update)
ترقية الإصدار دون مسح أي بيانات، مع لقطة تراجع للكود والقاعدة، وتراجع تلقائي عند الفشل
🚀 تحديث
⚡ أمر التحديث (بعد الخطوة 1 ونقل الحزمة الجديدة للفلاشة):
powershell -ExecutionPolicy Bypass -File E:\NOCI-Deploy\scripts\07-server-update-release.ps1
ما يفعله السكربت بالترتيب 
1. يفك الحزمة في مجلد مؤقت أولاً (حزمة تالفة تُكتشف قبل إيقاف أي شيء)
2. يوقف الخادم ويعطّل المهمة مؤقتاً
3. يحفظ لقطة في C:\NOCI\releases\pre-update-<الإصدار>-<التاريخ>\
     backend (الكود) + app\build\web + نسخة من attendance.db
4. يستبدل: backend\src  scripts  vendor  node_modules  package*.json  و app\build\web
5. يشغّل الخادم (ترحيلات القاعدة تُطبَّق تلقائياً) ويتحقق أن الإصدار = إصدار الحزمة

⚠️ تنبيه ذهبي:
عند التحديث لا تشغّل أبداً الخطوة 0 ولا 3. الخطوة 7 وحدها تتكفل بكل شيء وتحافظ على البيانات والمفاتيح والنفق. بعد التحديث: Ctrl+F5 في المتصفح.
