# 💻 دليل البناء والتشغيل والنشر على الحاسبتين (Windows & macOS)
## نظام البصمة والحضور لموظفي المقر — NOCI Attendance

يوثق هذا الدليل طريقة إدارة وتطوير وبناء النظام عبر الحاسبتين المعتمدتين وطرق التحكم بدورة حياة الخادم.

> **الإصدار الحالي: 2.0.0.** لتثبيت وتحديث إصدار جاهز راجع [دليل التثبيت والتحديث](دليل_تثبيت_الإصدار_2.0.0.md).

---

## 1. دورة تشغيل وإيقاف النظام على ويندوز (Server Lifecycle Management)

### التشغيل اليومي السريع:
- النقر مرتين على `تشغيل النظام.bat` في المجلد الرئيسي.
- يقوم السكربت بتشغيل الخادم، واستضافة حزمة الويب المبنية، وفتح المتصفح تلقائياً على المنفذ الثابت:
  `http://localhost:5000`

### كيفية إيقاف النظام (بدون إعادة تشغيل الكمبيوتر):
لإيقاف الخادم وتحرير المنفذ 5000 بنسبة 100%:
1. **الخيار 1 (المباشر):** إغلاق نافذة موجه الأوامر (CMD) بالضغط على `X` في زاوية النافذة أو `Ctrl + C`.
2. **الخيار 2 (السكربت السريع):** النقر مرتين على `إيقاف النظام.bat` في المجلد الرئيسي. يوقف أولاً مشرف التشغيل في الخلفية (`run-forever.js`) إن كان يعمل، ثم أي عملية على المنفذ 5000.
3. **الخيار 3 (سطر الأوامر PowerShell):**
   ```powershell
   Get-NetTCPConnection -LocalPort 5000 -ErrorAction SilentlyContinue | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
   ```
   > إذا كان الخادم يعمل عبر المشرف في الخلفية فأوقف المشرف أولاً، وإلا أعاد تشغيل الخادم خلال 3 ثوانٍ. لذلك يُفضَّل استخدام `إيقاف النظام.bat`.

### التشغيل في الخلفية مع إقلاع الويندوز:
- تشغيل `toolkit/install-startup-service.bat` مرة واحدة.
- يعمل الخادم عبر المشرف `backend/scripts/run-forever.js`، فيُعاد تشغيله تلقائياً عند أي تعطل، ويُكتب سجله في `backend/logs/server.log`.

### التشغيل عبر بيئة التطوير VS Code (مع شاشة Debug Console و Hot Reload):
- **الخادم الخلفي (API):** يعمل على المنفذ الثابت `http://localhost:5000`.
- **واجهة فلاتر للتطوير:** تم ضبط إعدادات VS Code في `.vscode/settings.json` و `.vscode/launch.json` لتثبيت المتصفح على المنفذ المخصص `http://localhost:8080` لمنع ظهور أرقام عشوائية مثل `51704`.
- **التشغيل الموحد بنقرة واحدة من VS Code:**
  - اختر من قائمة تشغيل VS Code (Run & Debug): `🚀 تشغيل النظام المتكامل` واضغط `F5`؛ سيقوم VS Code بتشغيل خادم Node.js في الخلفية وتشغيل فلاتر في المتصفح وربطه بالـ Debug Console لمراقبة كافة الأخطاء والرسائل مباشرة.

## 2. الحاسوب الأول: حاسوب ويندوز (Windows Main PC)
* **الدور:** بيئة التطوير والتشغيل الرئيسية واستضافة الخادم ونفق Cloudflare وتصدير نسخ (Web, Android, Windows).
* **المتطلبات المثبتة:**
  - Flutter 3.44.4+ مع Dart 3.12+
  - Node.js 24+
  - Cloudflared (للنفق الخارجي)

### الأوامر المعتمدة على ويندوز:
1. **تشغيل الخادم المحلي (Backend API):**
   ```powershell
   cd "d:\Employee NOCI\backend"
   npm install
   node src/app.js
   ```
   أو مع إعادة التشغيل التلقائية: `npm run start:supervised`
2. **تشغيل الاختبارات قبل أي بناء:**
   ```powershell
   cd "d:\Employee NOCI\backend"; npm test
   cd "d:\Employee NOCI\app"; flutter analyze; flutter test
   ```
3. **بناء وتصدير نسخة الويب (Web App):**
   ```powershell
   cd "d:\Employee NOCI\app"
   flutter build web --release --base-href "/"
   ```
4. **بناء وتصدير نسخة الأندرويد (Android APK):**
   ```powershell
   cd "d:\Employee NOCI\app"
   flutter build apk --release
   # الناتج: app\build\app\outputs\flutter-apk\app-release.apk
   ```
   > النسخة موقّعة بمفتاح التطوير وتصلح للتوزيع الداخلي فقط. النشر على Google Play يحتاج مفتاح توقيع رسمياً. إذا فشل البناء بخطأ "Could not close incremental caches" فتأكد من وجود `kotlin.incremental=false` في `android/gradle.properties`.
5. **بناء وتصدير نسخة ويندوز المكتبية (Windows Desktop App):**
   ```powershell
   cd "d:\Employee NOCI\app"
   flutter build windows --release
   # الناتج: app\build\windows\x64\runner\Release\ (يُضغط المجلد كاملاً للتوزيع)
   ```
6. **تجميع ملفات الإصدار:** تُنسخ ملفات التوزيع إلى `releases/vX.Y.Z/` (المجلد غير مرفوع إلى git). قبل البناء ارفع رقم الإصدار في `app/pubspec.yaml` و`app/lib/core/constants.dart` و`backend/package.json`.
7. **تشغيل نفق Cloudflare للربط الخارجي:**
   - الإعداد لأول مرة: `toolkit/setup-cloudflare-tunnel.ps1`
   - التشغيل:
   ```powershell
   cloudflared tunnel --config "$env:USERPROFILE\.cloudflared\config-attendance.yml" run noci-attendance-tunnel
   ```
   - بعد النشر أضف `HOST=127.0.0.1` إلى `backend/.env` حتى لا يُقبل اتصال غير مشفر من الشبكة المحلية.

## 3. الحاسوب الثاني: حاسوب ماك (macOS Mac Machine)
* **الدور:** بناء وتصدير نسخة الآيفون الرسمية (iOS App / IPA).
* **المتطلبات المثبتة على الماك:**
  - Xcode 15+ أو 16+ مع أدوات Command Line Tools
  - CocoaPods (`sudo gem install cocoapods` أو `brew install cocoapods`)
  - Flutter SDK متطابق مع إصدار الويندوز

### خطوات العمل على الماك خطوة بخطوة:
1. **نقل الكود المصدري:**
   - استنساخ المستودع عبر Git من الرابط المعتمد:
     `https://github.com/Speed3d/EmployeeNOCI.git`
2. **تجهيز مكتبات الـ iOS:**
   ```bash
   cd "Employee NOCI/app"
   flutter pub get
   cd ios
   pod install --repo-update
   cd ..
   ```
3. **التشغيل على محاكي الآيفون (iOS Simulator):**
   ```bash
   flutter run -d iPhone
   ```
4. **بناء حزمة الآيفون للإنتاج (iOS Archive / IPA):**
   ```bash
   flutter build ipa --release
   ```
5. **ربط التطبيق بالخادم:**
   - العنوان الافتراضي في تطبيقات الآيفون والويندوز هو `http://localhost:5000/api`، وفي الأندرويد `http://10.0.2.2:5000/api` (للمحاكي فقط).
   - على الأجهزة الفعلية: من شاشة الدخول اختر **"ضبط عنوان الخادم (API)"** وأدخل `https://Employee.nociraq.com/api`، ويُحفظ العنوان على الجهاز.
   - عبر النفق لا يحتاج المستخدم أن يكون على نفس الشبكة المحلية.
